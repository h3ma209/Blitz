Blitz Documentation & Reference Guide

Blitz is an ultra-fast, local-first API client and testing platform built with Rust and Dioxus. It delivers sub-150ms native startup, a ~10MB memory footprint, multi-protocol execution (HTTP, WebSockets, gRPC, MQTT, SSE, GraphQL, Socket.IO), native OS keychain encryption, branch-based Git synchronization, and a built-in 37-tool Model Context Protocol (MCP) server for AI coding agents.

💡 Why Blitz exists:

Mainstream API clients increasingly force cloud logins, upload proprietary company payloads to remote servers, charge hefty per-seat subscription invoices, and consume hundreds of megabytes of RAM running Electron/Node.js runtimes. Blitz runs completely on your own hardware, saves data as clean JSON on disk, uses your own Git repositories for team sync, and exposes a native stdio MCP server for autonomous AI agents (Cursor, Claude, Antigravity, Windsurf).

Core Architecture

Blitz avoids Electron entirely. It is written 100% in safe Rust, compiling to a lean native binary with zero webview overhead in headless mode.

Frontend / GUI

Dioxus Native 0.6 with cross-platform renderer. Renders at 60+ FPS with minimal GPU/CPU load.

Execution Engine

Tokio asynchronous runtime + Reqwest (HTTP/1.1 & HTTP/2) + Hyper-util client.

JavaScript Sandbox

Embedded Boa engine for Postman-compatible pre-request and test script execution.

Protocols & MCP

tokio-tungstenite (WS), hyper/prost (gRPC), rumqttc (MQTT), JSON-RPC 2.0 stdio (MCP).

Installation & Builds

macOS (Apple Silicon & Intel)
# Download prebuilt DMG or universal release binary from GitHub Releases:
curl -L -O https://github.com/h3ma209/Blitz/releases/latest/download/Blitz-macOS.dmg
Linux (x86_64 & aarch64)
curl -L -O https://github.com/h3ma209/Blitz/releases/latest/download/blitz-linux-x86_64.tar.gz
tar -xzf blitz-linux-x86_64.tar.gz && sudo mv blitz /usr/local/bin/
Build from Source (Rust 1.83+)
git clone https://github.com/h3ma209/Blitz.git
cd Blitz
cargo build --release
# Binary available at target/release/blitz

Collections & Request Workspace

Blitz organizes API suites into nested trees of Collections, Folders, Subfolders, and Request items. All items support custom headers, query parameters, authorization schemes, pre-request scripts, and test scripts.

⚡ Instant Tree Search & Inline Type Filters

The sidebar search input provides real-time, debounced filtering across request names, URLs, HTTP methods, headers, and payloads with zero UI lag. Filter by specific item types directly inside the search bar using inline prefix syntax:

Prefix Syntax Shorthand Example Query Filter Behavior
folder:<query> f:<query> folder:auth Filters folders only (keeps parent collection visible). folder: alone lists all folders.
req:<query> request:, r: req:users Filters request items only by name, URL, method, or payload. req: alone lists all requests.
col:<query> collection:, c: col:store Filters top-level collections only. col: alone lists all collections.
is:<type> / type:<type> — is:folder auth Alternative semantic filter syntax for folders, requests, or collections.

Request Body Modes

Select from standard request formats in the body tab:

  • none: No body sent (standard GET/HEAD).
  • raw: Payload with automatic Content-Type headers for JSON, Text, JavaScript, HTML, or XML.
  • form-urlencoded: Key-value parameters encoded into URL percent-escaped format.
  • form-data: Multipart upload supporting text values and binary file uploads.
  • graphql: Dual-pane editor for GraphQL query document and JSON variables.

Multi-Protocol Execution Engine

Blitz is engineered from the ground up for modern microservices and real-time architectures:

WebSockets (ws:// & wss://) tokio-tungstenite

Full bi-directional frame streaming with live connection log, automatic UTF-8 string/binary frame decoding, and manual or script-driven frame transmission.

gRPC (HTTP/2 Unary & Streaming) hyper + prost-types

Native gRPC unary RPC calls using google.protobuf.Struct JSON serialization. Returns exact gRPC status codes (0=OK, 1=CANCELLED, 14=UNAVAILABLE, etc.), status messages, and latency.

Server-Sent Events (SSE / EventSource) HTTP stream reader

Connect to event streaming APIs (e.g. OpenAI / Anthropic streaming responses). Collects event:, data:, and id: lines into structured timelines.

MQTT (IoT Broker Publish / Subscribe) rumqttc v0.24

Connects to standard brokers (Mosquitto, EMQX, HiveMQ) over TCP. Supports QoS 0, 1, and 2 publish operations and timeout-bounded topic subscriptions.

Socket.IO Client rust_socketio

Performs Engine.IO engine handshake, executes custom event emits with JSON arguments, and listens for targeted inbound server events.

GraphQL Subscriptions over WebSocket graphql-transport-ws

Connects to modern GraphQL subscription servers with connection_init handshake, executes subscription queries, and streams real-time updates.

Variables & Dynamic Faker System

Variables can be referenced anywhere in URLs, parameters, headers, or body payloads using {{variable_name}} syntax.

Variable Precedence Hierarchy

When resolving a variable token, Blitz inspects scopes in the following strict order (matching Postman convention):

Local / Script Scope > Data Iteration File > Active Environment > Collection Scope > Global Scope > Dynamic Faker > Unresolved

Postman-Compatible Dynamic Variables ($faker)

Blitz includes native evaluation for Postman dynamic pseudo-variables. These can be used in templates or generated inside scripts via pm.variables.replaceIn("{{$guid}}") or pm.variables.get("$guid"):

OS Keychain Secrets / Vault ({{vault:key}})

Sensitive tokens or passwords can be kept out of Git collection repositories entirely by prefixing them with {{vault:key}}. Blitz encrypts and resolves these directly from macOS Keychain, Linux Secret Service (libsecret), or Windows Credential Manager.

Scripting & Test Sandbox (blitz.* Native API)

Blitz includes an embedded JavaScript engine (Boa) that executes pre-request and test scripts. The native namespace is blitz.*, with pm.* and epm.* fully aliased for 100% backward compatibility with imported Postman collections:

// Native Blitz test script (also supports legacy pm.* syntax)
blitz.test("Status code is 200", function() {
blitz.response.to.have.status(200);
});

blitz.test("Payload schema and latency validation", function() {
var data = blitz.response.json();
blitz.expect(data).to.have.property("token");
blitz.expect(blitz.response.responseTime).to.be.below(500);
// Set extracted token into active environment
blitz.environment.set("authToken", data.token);
});

Available blitz.* Sandbox Objects

All objects below are available under blitz.* (and aliased as pm.*):

  • blitz.environment.get(k) / .set(k, v) / .unset(k) / .clear()
  • blitz.collectionVariables.get(k) / .set(k, v)
  • blitz.globals.get(k) / .set(k, v)
  • blitz.variables.get(k): Resolves across all scopes including dynamic $guid.
  • blitz.variables.replaceIn(str): Replaces {{variables}} in a string.
  • blitz.response.code: HTTP status integer (e.g. 200).
  • blitz.response.json(): Parsed response JSON object.
  • blitz.response.text(): Raw response body string.
  • blitz.response.headers.get("Content-Type"): Response header inspection.
  • blitz.sendRequest(url, callback): Execute sub-requests inside pre-request scripts.
  • blitz.visualizer.set(template, data): Render interactive HTML response visualizers.
  • require("crypto-js"): Native SHA-256 and HMAC-SHA256 crypto support.

Model Context Protocol (MCP) Server for AI Agents

Blitz includes a built-in Model Context Protocol (MCP) server over standard input/output (blitz mcp). Autonomous AI coding assistants (Cursor, Claude Desktop, Antigravity / Gemini, Windsurf, VS Code, and Zed) can query collection schemas, execute HTTP and multi-protocol endpoints, run load benchmarks, extract environment variables, and manage cookies locally without cloud dependencies.

Automatic IDE Configuration (blitz mcp setup)

Blitz can scan your machine for installed AI IDEs and automatically inject the MCP server configuration:

# Interactive scanner & configuration tool:
blitz mcp setup

# Configure all detected IDEs automatically:
blitz mcp setup --all

Git Sync & Headless CI/CD Automation

Blitz treats Git as a first-class storage provider. Workspaces can be synchronized directly to GitHub, GitLab, Gitea, or self-hosted remotes without proprietary cloud intermediaries.

Headless CLI Runner (blitz run)

Execute test suites directly inside GitHub Actions, GitLab CI, or local terminals:

# Run collection with staging environment:
blitz run ./collections/api.json --env ./environments/staging.json

# Run with 10 iterations, data CSV, and JUnit report output:
blitz run ./collections/api.json -d ./test_data.csv -n 10 --reporters cli,junit --reporter-junit-export ./report.xml

Exit Codes

  • 0: All requests and assertions passed.
  • 1: One or more assertions failed or request network error occurred.
